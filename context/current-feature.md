- **2026-08-14** — Email Verification Toggle + Silent-Failure Fix completed on `feature/email-verification-toggle`. Added `EMAIL_VERIFICATION_ENABLED` (`src/lib/verification-email.ts`'s `isEmailVerificationEnabled()`, defaults to enabled unless explicitly `"false"`) so verification can be turned off entirely for environments without a verified Resend sending domain — with it off, `POST /api/auth/register` creates users already `emailVerified` and skips the Resend call altogether, and `authorize()`/`resend-verification` both short-circuit around the check. While wiring this up, found and fixed a real bug in the original feature: `resend.emails.send()` resolves with `{ data, error }` rather than throwing on API failures, so the original `try/catch` around it could never actually catch a failed send — registration always reported success even when no email went out. `POST /api/auth/register` now checks that `error` field and throws, and with the flag on, a failed send rolls back the just-created user and returns a real `502` instead of a silent success. Verified end-to-end against the live dev server with the flag both off (auto-verified user, sign-in succeeds immediately, no Resend call attempted) and on (a send guaranteed to fail via Resend's sandbox restriction now correctly returns `success: false` and leaves no orphaned user; a send to the Resend account's own address still succeeds as before). `npm run build` and `npm run lint` both pass.
