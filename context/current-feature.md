Added `src/lib/db/collections.ts` with `getRecentCollections()` and `getCollectionStats()`, querying Prisma directly (no auth wired up yet, so it looks up the demo user by email like the seed script does). `dashboard/page.tsx`'s "Recent Collections" section and the Collections/Favorite-collections stats now come from the Neon database instead of `lib/mock-data.ts`; items/pinned/recent-items sections stay on mock data since items aren't migrated yet. `CollectionCard` now derives its dot color from the most-used item type in the collection and shows small icons for every type present. Added `prisma/seed.ts`, wired up via `migrations.seed` in `prisma.config.ts` (Prisma 7 config, not a `package.json#prisma.seed` key) and run with `npm run db:seed` (`prisma db seed`). Added an optional `password` field to `User` (bcrypt hash, null for OAuth-only accounts) via a new migration, since credentials auth isn't wired up yet but the spec needed somewhere to store the demo password hash — installed `bcryptjs` for hashing (12 rounds). Seeds the demo user (`demo@devstash.io` / `12345678`), the 7 system `ItemType`s, and 5 collections (React Patterns, AI Workflows, DevOps, Terminal Commands, Design Resources) with their items per `context/features/seed-spec.md`. Script is idempotent: user/item-types use upsert-or-find, and collection/item seeding is skipped entirely if the demo user already has collections. `npm run build` and `npm run lint` both pass.
- **2026-08-10** — Prisma 7 + Neon PostgreSQL setup completed on `feature/prisma-neon-setup`. Added `prisma.config.ts` (Prisma 7 moves datasource URL config out of `schema.prisma` into this file) and `prisma/schema.prisma` with the `prisma-client` generator (replaces `prisma-client-js`, outputs to `src/generated/prisma`, gitignored, generated via `postinstall`). Schema covers NextAuth's `Account`/`Session`/`VerificationToken`/`User`, plus `ItemType`, `Item`, `Collection`, `ItemCollection` (join table), and `Tag`. Resolved the three open questions from `project-overview.md`: `Tag` is scoped per-user (`@@unique([userId, name])`, not global), `ItemType.color` stays required with no schema-level fallback, and `Collection.defaultTypeId` uses an explicit `"CollectionDefaultType"` relation name to avoid colliding with `Item.itemTypeId`. Client is instantiated via the Neon serverless driver adapter (`@prisma/adapter-neon` + `@neondatabase/serverless` + `ws`) in `src/lib/prisma.ts` — Prisma 7 requires an explicit driver adapter, there's no more implicit query engine connection. Ran `prisma migrate dev --name init` against the Neon dev branch; `npm run build` and `npm run lint` both pass. NextAuth itself (the `next-auth`/`@auth/prisma-adapter` packages, sign-in flows) is not wired up yet — only the DB models it needs are in place.
